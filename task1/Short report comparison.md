In the imperative version with jQuery, the developer changes the DOM directly. The code gives step by step instruction to the browser. When the button is clicked, jQuery finds the paragraph and adds or removes the highlight class. The programmer controls each action manually. This approach focuses on how the UI changes. In the React version, the approach is declarative. We don’t change the DOM directly. Instead, we describe how the UI should look depending on the state. React updates the interface automatically.
React uses state and re-rending. In this task, the state variable isHighlighted controls the paragraph style. When the button is clicked, the state changes. React re-renders the component and updates the UI. We don’t write commands like “find element” or “change class”. React does this automatically.
This example matches Ch1, “Declarative UI structures”, because the UI is described by state, not by manual DOM operations. It also relates to “Data changes over time”, since the interface updates when data (state) changes.
The declarative approach is better for large applications. Imperative code becomes difficult when there are many elements and interactions. Developers must manage many DOM updates manually. In React, components organize UI and logic together. This makes the code easier to read, maintain, and reuse. As the project grows, declarative structure keeps the app more organized and less error-prone.
